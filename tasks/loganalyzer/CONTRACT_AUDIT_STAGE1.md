### Method

1. `git fetch origin main`; audited a detached worktree of `origin/main` (removed at the end). Path/line references below are on that SHA.
2. Re-measured freshness of every existing audit document (table below) before reusing anything.

5. Ran the test suites here with the .NET 10.0.401 SDK in the scratchpad (`-p:EnableWindowsTargeting=true`): `LogAnalyzer.Dfir.Tests` = 280 tests, **193 pass / 59 fail / 28 skip**; `LogAnalyzer.UI.Tests` = 120 tests, **114 pass / 6 fail**. All 65 failures were classified by exception type as platform-caused (Linux has no ACL APIs, `wintrust.dll`, `wevtutil`, `powershell.exe`, `auditpol`, Windows path semantics, DPAPI/SqlCipher). 6. Anything not provable from code or a run is marked "unverified".

### Classification rule used

- IMPLEMENTED: exists, has a real production consumer, and has at least one test. Where the only tests need the owner's private corpus (skipped in CI) the row says so and is rated PARTIAL instead.
- PARTIAL: exists and is wired but the contract is not fully met (gap says which part).
- UNWIRED: code exists, no non-test production consumer.
- MISSING: not present (a field declared but never populated counts as MISSING for the behaviour).

### 2a. Top 10 gaps (ranked by what blocks the Definition of Done R23 and the release gate R22)

1. **No verification layer (InspectraVeritas).** R10.0-R10.V7, R9.7, R15.2, R16.5, U13, U24.7. No verdicts (VERIFIED/SUPPORTED/CONTRADICTED), no contradiction handling (`Finding.ContradictingEvidence` is declared and never set, `DC/Model/Analysis.cs:66`), no independent audit. Blocks 'independently verified' in R23 and the AI-claim / unresolved-findings gates in R22.
2. **Audit and custody are not tamper-evident.** R16.10, R3.7, R22.7. `CaseWorkspace.Audit`/`Custody` append plain lines (`DC/Case/CaseWorkspace.cs:136,156`); only the policy audit is hash-chained (`DC/Policy/PolicyExecution.cs:279`). Findings, report and exports are not registered in custody. Blocks the 'audit integrity' gate.
3. **Forensic validation cannot be reproduced in CI and no release gate exists.** R22.1-R22.8, R21.4-R21.6. CI shows 'FORENSIC VALIDATION = UNAVAILABLE (0/21)' as a warning only; corpus/differential runs are owner-machine only; Prefetch and SRUM have corpus-only tests; $MFT is absent. No waiver format, no CodeQL for C#.
4. **Shell contradicts the UX contract and R2.2: static reassurance.** U3, R2.2, R1.2, U23. `App/MainWindow.xaml:237,240` ('ALL SYSTEMS NORMAL', 'SHIELD ARMED & SECURE'), `App/Views/DashboardView.xaml:24,128` ('EVIDENCE VAULT SECURED', 'EDR CONTAINMENT ACTIVE ... armed' while auto-containment is off by default), `MainViewModel.cs:114,147`. These display safety with no evidence behind them.
5. **Legacy code still asserts compliance and attribution without evidence.** R12.3, R5.3, R5.2, R4.18. `Core/Services/ComplianceAuditEngine.cs:29,41,52,75` ('CONFORM' unconditional or on absence of events) shown in `ActiveDirectoryAuditView`; page titled 'APT Attribution'; `ExecutionProven` enum; 17 unwired parsers (carrying `ExecutionProven` and about 22 empty catches) and 10 unwired services.
6. **Finding model does not meet the contract; no common state vocabulary.** R5.1, R19.*, R20.*, U19. No SemanticType, Verification, Limitations, Provenance, AuditTrail or message keys; six different state enums coexist; only 4 of the 10 standard states have any representation. Every UI/report/Vault consumer inherits this.
7. **No localisation or accessibility foundation, and navigation is by module.** U2, U7, U17, U18, R17.1, R18.1-R18.12. No resx, 0 `AutomationProperties`, hard-coded Romanian/English mix, none of the 12 plain-language terms exist, Verify/Memory/Reports have no page.
8. **Response verification is inconsistent.** R13.4-R13.7, R22.6. Policy engine and `SystemDefenseExecutionService` verify by re-read; process containment records `Success` after the firewall COM call returns (`DW/Containment/ProcessContainmentService.cs:98-101`) and has no NOT_VERIFIED state.
9. **Backend results are invisible or not reusable in the app.** R7.8, R9.1, U16, U4-U6. Detections, rule inventory, parser inventory and Vault proposals have no UI; results live only in memory (no 'open existing case'); evidence/why/unknowns are not shown in the findings grid; timeline view silently truncates at 20,000 rows (`INVVM:177`); folder import skips most artifact types (`INVVM:105-108`).
10. **Reporting is a single technical PDF and machine-readable output is a set of loose files.** R14.1-R14.9, U15. No executive/audit/complete profiles or audience selector, no export manifest/schema, OSCAL not schema-validated, report and evidence lists truncated (`DW/Investigation/InvestigationReportPdf.cs:73,99`).

Also worth knowing (not in the top 10): the new DFIR stack is genuinely wired and well evidenced for acquisition, preflight, 16 registered parsers, correlation, graph, local AI, policy and Vault-proposal export. The gap is mostly *above* that stack (verification, contract model, UI) and *beside* it (legacy shell, CI gate).

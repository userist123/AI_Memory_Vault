- `core/aas_build/runner.py`: fixed-argv `docker run` (no shell, `--network none`, `--read-only`, `--tmpfs /tmp:rw,exec,nosuid,nodev`,
  cap-drop ALL, no-new-privileges, uid 1000, 2 cpus, 2g, pids 512, digest-pinned image or image id), timeout + `docker kill`,
  output read only after exit AND container gone (`docker container inspect`), reader fails on symlink / junction (reparse) /
  hardlink / non-regular file / bad name / extension outside the allow-list / control file names / missing index.html /
  count+size caps (defaults 1000 files, 50 MB file, 200 MB total); copies to a staging dir, atomic rename, `distSha256`.

  `Host: p-<id16>.localhost:<port>` exactly, GET/HEAD only, full header set (CSP, Permissions-Policy, COOP, CORP,
  X-Frame-Options, nosniff, no-referrer, no-store) on EVERY response including 4xx/5xx, no listing (only `/` -> index.html),
  no dotfiles/ADS/backslash/`..`, lstat walk refuses symlink/junction/hardlink, own MIME table (Windows registry independent).

## Findings worth knowing
- Docker `--tmpfs` defaults to `noexec`: vite/rolldown need `exec` (`/tmp:rw,exec,nosuid,nodev,size=1g`). DESIGN 3.4 omitted it.
- pnpm registers the project inside its store even with `--offline`; the baked store is read-only, so the entrypoint builds
  a writable store shell in /tmp with symlinks to the baked `files`/`index`.
- Docker Desktop bind mount on Windows DOES let the container create a symlink in /out (so the reader check is load-bearing).
- X-Frame-Options SAMEORIGIN is sent as requested; Chromium ignores it when CSP `frame-ancestors` is present (needed for the Tauri origin).

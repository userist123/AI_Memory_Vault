# Slice S3 - build pipeline + preview server (2026-11-23)

Branch `claude/aas-s3` (local only). Owns `images/**`, `kit/**`, `core/aas_build/**`, `tests/build/**`, this file.

## What
- `kit/`: studio-owned `package.json` (React 19.3.1, Vite 8.3.8, @vitejs/plugin-react 6.3.0, TypeScript 7.0.2,
  @capacitor/core|cli|android 8.6.2, all exact), `pnpm-lock.yaml` (pnpm 10.28.2), `pnpm-workspace.yaml`
  (`minimumReleaseAge: 10080`, `strictDepBuilds`, `onlyBuiltDependencies: []`), `.npmrc` (`ignore-scripts=true`),
  `vite.config.ts`, `index.html` (meta CSP = defense in depth), `capacitor.config.ts`, `tsconfig.json`,
  `template/src/` (blank React app the studio materialises into `src/`). Lock has 0 `requiresBuild` packages.
- `images/web-build`: node 24.22.3-alpine pinned by digest, pnpm 10.28.2, kit deps installed ONCE at image build
  (`pnpm install --frozen-lockfile --ignore-scripts`) into `/opt/aas/kit/node_modules` (root-owned, `go-w`, read-only
  rootfs at run time, exec allowed because it is not a tmpfs). `aas-build-web` copies /src to /tmp/w, refuses any
  lockfile whose sha256 is not the baked one (exit 3, `unapproved lockfile (sha256 X is not the approved Y)`), refuses
  a `node_modules` in the source (exit 4), creates a tmpfs `node_modules/` whose entries are symlinks into the baked
  one (vite needs to write `node_modules/.vite-temp` for the bundled config) and runs
  `node /opt/aas/kit/node_modules/vite/bin/vite.js build --outDir /out/dist`. Nothing is installed at run time.
- Lockfile selection is fail-closed by lockSha: one image = one approved lockfile. A project with another lockfile
  needs an approved `aas-store-<lockSha>` image built by the install slice (DESIGN 3.3); until then its build fails with exit 3.
  Build: `docker build -f images/web-build/Dockerfile --build-context scripts=images/web-build -t aas-web-build:dev kit`.
- `images/proxy`: dependency-free Node CONNECT proxy, only `registry.npmjs.org:443`, public-address-only upstream.
  `isPublic` uses two `net.BlockList`s (IPv4 and IPv6 separately: Node maps IPv4 into `::ffff:0:0/96`, so one mixed list
  would deny every IPv4 address). Refused: RFC1918, loopback, link-local, CGNAT, 198.18/15, documentation, multicast,
  reserved/broadcast, `::`/`::1`/IPv4-compatible, IPv4-mapped, NAT64 (`64:ff9b::/96`, `64:ff9b:1::/48`), 6to4 `2002::/16`,
  Teredo, discard, ULA, link-local, site-local `fec0::/10`. A name resolving only to refused addresses -> `403`
  (not 502). Exports `{isPublic, safeLookup, start}`; listens only when run as main.
  Build: `docker build -f images/proxy/Dockerfile -t aas-proxy:dev images/proxy`.
- `images/android-build`: Dockerfile skeleton + README with the exact remaining steps (NOT built: needs 3-5 GB, a
  verification-metadata CI step and three pins). Verified facts: Capacitor 8.6.2 compileSdk 36, AGP 8.13.0, template Gradle 8.14.3.
- `core/aas_build/runner.py`: fixed-argv `docker run` (no shell, `--network none`, `--read-only`, `--tmpfs /tmp:rw,noexec,nosuid,nodev,size=1g`,
  cap-drop ALL, no-new-privileges, uid 1000, 2 cpus, 2g, pids 512, `--ulimit fsize=64MB`, digest-pinned image or image id),
  `Popen` with stdout/stderr pumped into 1 MB ring buffers (log tail = end of stdout + end of stderr, max 4000 chars),
  a watchdog that kills the container when `/out` grows past `limits.max_total_bytes`, timeout + `docker kill`; on ANY
  failure the out dir is deleted. `docker_container_exists` returns False only on "No such container/object"; any other
  daemon error raises (fail closed). Output read only after exit AND container gone, reader fails on symlink / junction (reparse) /
  hardlink / non-regular file / bad name / extension outside the allow-list / control file names / missing index.html /
  count+size caps (defaults 1000 files, 50 MB file, 200 MB total); copies to a staging dir, atomic rename, `distSha256`.
  Only module that imports subprocess (AST test).
- `core/aas_build/preview_server.py`: `PreviewServer(site_root_for, port=17880)`, binds 127.0.0.1 only, project from
  `Host: p-<id16>.localhost:<port>` exactly, GET/HEAD only, full header set (CSP, Permissions-Policy, COOP, CORP,
  X-Frame-Options, nosniff, no-referrer, no-store) on EVERY response including 4xx/5xx, no listing (only `/` -> index.html),
  no dotfiles/ADS/backslash/`..`, lstat walk refuses symlink/junction/hardlink, own MIME table (Windows registry independent).
  400 with the full header set for invalid percent-encoding / invalid UTF-8 (`/%ff`, `/%c0%af`), non-ASCII paths,
  duplicate `Host`, malformed request lines and HTTP/0.9 requests (`default_request_version = HTTP/1.1`, otherwise
  http.server answers without status line or headers); error bodies never reflect the request line. 10 s idle socket
  timeout (slowloris), at most 32 concurrent connections (extra ones are closed at accept).

## Findings worth knowing
- vite runs from the image's node_modules, so /tmp stays `noexec` (DESIGN 3.4). vite 8 writes the bundled config to
  `<nearest node_modules>/.vite-temp`: node_modules must be a real writable dir, hence the per-entry symlinks.
- Docker Desktop bind mount on Windows DOES let the container create a symlink and a hardlink in /out (so the reader
  checks are load-bearing).
- X-Frame-Options SAMEORIGIN is sent as requested; Chromium ignores it when CSP `frame-ancestors` is present (needed for the Tauri origin).

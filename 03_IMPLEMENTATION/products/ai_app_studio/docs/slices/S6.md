# Slice S6 - built-in runner + wiring into one app (2026-11-23)

Branch `claude/ai-app-studio` (local commits only, nothing pushed). Builds on S1-S5.

## What
- `core/aas_runner/` - built-in runner. `claude.py`: `build_argv` (DESIGN 6.1: prompt on stdin, `--strict-mcp-config`
  with only `ai-app-studio`, `--tools ""` + allow-list of the catalogue tools, `--disallowedTools` for every built-in
  that touches files/shell/network, `--setting-sources ""`, `--settings` studio file, `--max-turns`, `--max-budget-usd`,
  `--include-partial-messages`), `runner_env` (SYSTEMROOT, PATH, USERPROFILE, APPDATA, LOCALAPPDATA only; no `AAS_*`, no
  tokens), `Runner.start/stop/wait/is_running` (cwd = fresh EMPTY `<data>/runner/runs/<runId>`, TEMP outside it, process
  tree killed on stop/timeout, grant and run dir removed at the end). `streamjson.py`: `StreamMapper` (per event type
  field allow-list; thinking dropped and counted; tool results = size + sha256 + 300-char redacted excerpt; `result` ->
  `cost.update` + `run.finished`; text deltas line-buffered and redacted; unknown types counted into one
  `stream.dropped`), `check_init` (P5e/N3: `mcp_servers` must be exactly `["ai-app-studio"]`, tools a subset of the
  catalogue, else the run is aborted and the process killed).
- `core/studio_core/run_grants.py` - the built-in runner is not an "external" MCP client: its MCP child gets a per-run
  secret in its own env; only sha256 of it is stored while the run lives; the MCP server accepts a call with a live
  grant (bound to ONE project) or when the owner enabled external MCP (PX1 unchanged).
- MCP server (`apps/mcp-app/server.py`): grant/owner guard, `plan_submit`, `app_build` (real), `device_start|install|tap|
  screenshot`, `file.diff` events on `code_write_file`, `project_list` limited to the run's project under a grant.
- `core/aas_build/service.py` - project files + studio kit -> `docker run --network none` (S3 runner) -> `site-<ms>` +
  atomic `current` pointer -> preview server; events `build.started`, `build.log`, `build.error`, `build.finished`,
  `preview.captured`; one build at a time; a failed build keeps the last good site. `python -m aas_build` = preview
  server (17880). N1: the S3 watchdog now also kills the container above `max_files` (and `resolve_image`).
- `core/aas_device/service.py` - device tools behind the owner setting `device_enabled` (default OFF, owner-only
  route `PUT /api/v1/settings/device`), refused below 8 GiB free on the system/LOCALAPPDATA drive or when the S5
  preflight fails; only `apps.device_host.launcher.preflight` / `DeviceSession` are used.
- Backend (follow-ups from S2/S4 reviews): `GET /approvals` (generic + `kind:"plan"` records), `POST /approvals/<id>/decide`,
  `POST /plans/<id>/decide` (`approve` | `edit`), `POST /runs`, `POST /runs/<id>/stop` - owner token only, agent actors
  refused by policy (`plans.py`); activity kinds `cost.update`, `preview.captured` (migration 0004) and field names the
  UI reads (`title`, `budgetUsd`, `stepId`, `callId`, `target`, `line`, `path`, `revision`); sanitiser: DCS stops at
  newline/CR/end, OSC also at CR, U+034F/U+115F/U+180E/U+3164 dropped; `audit.redact` F1 (digest kept under hash keys)
  and F2 (keys sanitised first). `AAS_DEV_ORIGINS` (strict `http://127.0.0.1:<port>`, process env only) lets the vite
  dev/preview UI call the API; the preview server's `frame-ancestors` gets the same origins (opt-in).
- Desktop: `clean()` drops and `inspect()` flags the four fillers, CSI needs its final byte, `prj_<hex>` ids map to the
  preview host label, iframes reload on every `preview.captured`/`preview.revision` (`previewNonce`; a `file.diff`
  already raises the revision before the build is done), Tauri attach mode (`AAS_ATTACH_BACKEND=1`, token on stdin),
  the shell now starts `python -m apps.backend` (the old `main.py` path could not import its package),
  `apps/desktop/scripts/studio_window.mjs` (Chromium window with the session injected, token on stdin).
- `scripts/run_studio.ps1` - one command: token (CSPRNG, memory only) -> backend on stdin -> preview server -> vite dev ->
  Tauri debug exe (or Chromium window) with the same token on stdin -> everything stopped on exit. `-Prompt/-PromptFile`
  creates a project and starts a run; `-RunnerCli` swaps the agent CLI (fake fixture); `-NoUi` for tests.

## Residuals / open items
- The UI has no "start a run" control yet: runs start from `run_studio.ps1 -Prompt`, `POST /api/v1/runs` or an owner
  enabled external Claude Code. A prompt box is the next UI task.
- P5f is NOT enforced: `plan_submit` + owner decision exist, but `code_write_file` does not require an approved plan and
  the runner does not wait for `plan.decide` (two-phase run) - needs the owner toggle (DESIGN 5.5).
- `app_build` streams its log only after the build ends (the S3 runner keeps ring buffers); Android build, device install
  of an APK and `preview_capture` are still `unavailable`; all device probes stay deferred (C: < 8 GiB at S5 time).
- `tool.call` rows written by `Studio.operation` carry no run id/callId (DESIGN 5.3 residual 4); file bodies are not
  streamed as `agent.typing` (only text deltas are).
- Real agent runs were not executed (no model spend); everything above used the fake CLI and the real CLI only up to `system/init`.
- Playwright needs `chromium_headless_shell` of the pinned version (`playwright install chromium-headless-shell`);
  here it lives in `D:\w\_aas_pw` (`PLAYWRIGHT_BROWSERS_PATH`). Headed Chromium 1255 crashed at start on this OS build
  (exit 0x80000003); the Tauri window is the owner-facing UI, so `-Ui window` is untested.
- Caches kept on D: (owner rule): `_aas_uvcache`, `_aas_pnpm`, `_aas_pw`, `_aas_cargo_target`, `_aas_cargo_home`.

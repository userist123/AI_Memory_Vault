## What
1. **Live emulator mirror** (DESIGN 2.3, 5.4, 5.5). The device session lives in the run's MCP child, so the video crosses
   a process boundary:
   - `core/aas_device/video_relay.py` (stdlib only). `VideoHub.open_run(run, project)` creates a per-run
     `multiprocessing.connection` Listener on a random pipe name (`\\.\pipe\aas-video-<128-bit hex>`) with a 256-bit key;
     both sides prove the key (HMAC challenge) before any byte is read; only `recv_bytes(MAX_CHUNK)` (never `recv`, nothing
     is unpickled); one sender at a time; wrong-key attempts are counted and throttled; `close_run` at run cleanup.
   - The runner (`aas_runner.claude.Runner(video_hub=...)`) puts `AAS_VIDEO_PIPE`/`AAS_VIDEO_KEY` into the MCP child's env
     only (the run's mcp.json, like the run grant); the agent CLI's env never has them (test).
   - MCP child: `DeviceService.start` starts a `VideoSender` when that env exists: `video_start` on the device host, then
     chunks from the bounded `DeviceSession.video_q` (oldest dropped first, N7) to the pipe; stopped with the device.
   - Hub caps: chunk <= 64 KiB (bigger drops the sender), 2 MiB/s token bucket per project (excess dropped, stream marked
     discontinuous), NAL <= 1 MiB (else the splitter resets), GOP cache <= 4 MiB, <= 2 viewers per project, 4 MiB queue per
     viewer, WS frames <= 64 KiB. The hub re-cuts the stream at NAL boundaries: a viewer gets whole NALs only, starting with
     SPS + PPS + IDR (late viewers: cached SPS/PPS + current GOP); a slow viewer loses whole NALs and resumes at the next
     IDR. Video is never stored.
   - Backend WS `/api/v1/device/video?projectId=prj_<16 hex>`: same boundary (token, exact Host, Origin) and subprotocol
     rules as `/events` (`aas.v1` selected, token never echoed, 4400 without `aas.v1`), 4422 bad id, 4404 unknown project,
     4429 over the viewer limit; binary frames only, nothing read from the client.
   - UI: `lib/video.ts` `VideoClient` (per project, binaryType arraybuffer, refuses a socket without `aas.v1`, frames
     > 64 KiB or > 4 MiB/s close the socket so the reconnect restarts a clean stream; reset on every open), worker messages
     `live`/`chunk`/`reset`, `lib/mirror.ts` `createLiveFeeder` (streaming Annex-B with cuts anywhere -> access units ->
     `VideoDecoder`, codec from the SPS, `isConfigSupported` first, key frame first, decoder queue > 30 drops deltas until the
     next key frame, 2 MiB buffer cap). `EmulatorMirror` takes `live={session, projectId}`; App subscribes for the current
     run's project (`prj_...`), demo mode keeps the fixture.
2. **Capture thumbnails**. `api.fetchCapture` (GET `/api/v1/captures/<sha256>` with the bearer token; id checked before the
   request; `image/png`, <= 8 MiB, PNG magic, **sha256 of the body must equal the id**) -> Blob -> `blob:` URL
   (`lib/captures.ts` LRU of 32, evicted URLs revoked). Store keeps the last 24 `preview.captured` (sha256, frame,
   revision); `CaptureStrip` in the timeline (newest first) and `CaptureThumb` under the active device frame, label
   "Phone 390×844 · rev N"; a failed/mismatched load shows "capture unavailable", never a broken image. Studio CSP
   `img-src 'self' blob:` (data: removed). `build_web` now announces `preview.revision {revision}` (dist digest moved to
   `build.finished.artifactSha256`), so `preview.captured` always names a real PNG.
3. **Nested-Virtualization modal**: emulator 31.3.9's own `emulator -help` lists `-no-nested-warnings  Disable the warning
   dialog when emulator is running in nested virtualization` (qemu-system-x86_64 also holds `no_nested_warnings` and the
   `showNestedWarning` setting key). `aas_devhost.emulator_argv` adds it; nothing is written to any HOME, no X11 input.
   MANIFEST.sha256 updated (`aas_devhost.py` `2b8a06af...`), installed with `wsl/install.ps1` (all 6 files verified through
   `\\wsl.localhost`). The `xwininfo` watch + `modal` event remain as the fallback.
4. **L1 licence hash** verified online: matches (details in S7.md L1). No change, no rebuild.

## S8 review fixes (2026-11-23, M1 + L1-L4)
- **M1 mirror recovery** (`core/aas_device/video_relay.py`, `apps/device_host/launcher.py`, `apps/desktop/src/lib/video.ts`,
  `lib/mirror.ts`, `workers/decoder.worker.ts`, `components/EmulatorMirror.tsx`):
  (a) a synced viewer now receives every NAL including a later SPS/PPS (screenrecord restart with new parameters);
  an unsynced viewer still gets SPS + PPS in front of its next IDR.
  (b) pipe messages = 8-byte big-endian seq + h264; `VideoSender` skips a seq when the host's chunk seq jumps, a chunk is
  marked `gap` or a chunk is unusable; the launcher, when its queue is full, drops whole chunks and marks the chunk after
  the hole (`gap`, also when the new chunk itself could not be queued). Hub: seq != last + 1 -> `seqGaps`, splitter
  reset, GOP dropped, viewers desynced (resume at the next IDR with SPS + PPS) and a throttled (2 s) `KEY_REQUEST` back
  on the pipe; the sender forwards it to `session.video_keyframe()` when the session has one (the device host has no such
  op yet: residual R2 in THREAT_MODEL.md). A new sender starts a new stream (never stitched). WS frames = 4-byte seq
  (1, 2, ... per socket) + whole NALs <= 64 KiB; a viewer-side drop skips one seq. The client checks the seq (first must
  be 1); a gap, like a decoder error, calls `VideoClient.resync()`: socket replaced after a bounded doubling backoff
  (0.5 s -> 8 s, back to 0.5 s after 30 s quiet), the server primes cached SPS/PPS + GOP, the new SPS configures a new
  decoder.
- **L1** the Listener has no authkey; the accept loop only accepts and hands each connection to a short-lived thread that
  runs `deliver_challenge` + `answer_challenge` through a deadline proxy (every recv polls until AUTH_TIMEOUT = 2 s);
  at most 4 pending handshakes (more are closed), wrong key keeps its slot 0.2 s (throttle), one sender at a time
  (`busy`), all threads end within AUTH_TIMEOUT after close_run.
- **L2** the late-viewer prime (SPS + PPS + GOP) is at most PRIME_MAX = 2 MiB (bigger: the viewer waits for the next IDR)
  and is not counted against the 4 MiB live queue; GOP cache cap 4 -> 2 MiB. Client: 4 MiB + 64 KiB per second plus
  2 MiB + 64 KiB in the first second after open (prime + hub burst + rate fit).
- **L3** decision: the per-project video WS persists across runs (the UI subscribes per project); at run end `close_run`
  drops the project's cached SPS/PPS/GOP and desyncs its viewers, so nothing stale is served; the socket stays open and
  idle and the next run resumes on it with SPS + PPS + IDR. Documented in `video_relay.py`, `video.ts`, DESIGN-level in
  THREAT_MODEL.md.
- **L4** THREAT_MODEL.md: new section "S8 surface: mirror pipe + video WS" (assets, attackers, controls, probes PV1-PV11,
  accepted residuals incl. R1 "pipe key in the run's mcp.json").

# Slice S7 - Android APK build, install on the studio emulator, preview capture, S6 low items (2026-11-23)

Branch `claude/ai-app-studio` (local commits only, nothing pushed). Builds on S1-S6.

## What
- `images/android-build` built for real (see its README): every download pinned by sha256 with `ADD --checksum`
  (Temurin 21.0.13.1+2, platform-36_r02, build-tools 36.0.0, Gradle 8.14.3-bin; Android zips also matched against the
  sha1 in Google's repository2-3.xml), base images by digest, `cap add android` template from the kit lockfile plus a
  studio overlay, read-only Gradle cache (`GRADLE_RO_DEP_CACHE`) and `gradle/verification-metadata.xml` written by one
  online resolve at image build, non-root. Image 2.0 GB (`sha256:936aa4ff...`, rebuilt for M2 as `sha256:1418afea...`, recorded in `images/DIGESTS.json`).
  - The kit pins `@capacitor/android` **8.6.2** (not 8.5.2): compileSdk/targetSdk 36, AGP 8.13.0 - asserted in the image.
  - cmdline-tools 23 refuses `sdkmanager --licenses` ("no longer needed") and its replacement `android` downloads an
    unpinned CLI; the licence acceptance is written as the sha1 of the licence text, nothing is installed at app build
    time (`android.builder.sdkDownload=false`).
  - Run: `--network none --read-only`, `/tmp` tmpfs **noexec** (works: Gradle/JDK run from `/opt`, aapt2 from the pinned
    build-tools via `android.aapt2FromMavenOverride`, `org.gradle.native=false`), `--memory 4g --cpus 4`, cap-drop ALL,
    no-new-privileges, uid 1000, `/dist` (current web build) and `/keys/aas-debug.keystore` read-only, `/out` the only
    writable mount. Gradle `--offline --no-daemon --dependency-verification strict`.
- Studio debug key: generated once by the image (`genkey`) into `%LOCALAPPDATA%\AIAppStudio\keys\aas-debug.keystore`
  plus `aas-debug.cert.sha256`; the argv builder refuses any other key file name and any path through an `.android`
  directory. The image checks with `apksigner` that the APK has exactly one signer equal to the mounted key; the host
  then compares that digest with the recorded one (PB7b).
- `core/aas_build/runner.py`: `build_android_argv`, `build_genkey_argv`, `ensure_keystore`, `collect_apk` (exactly one
  regular `app-debug.apk`, no link, nlink 1, ZIP magic, <= 100 MB, atomic copy), `run_android_build` (watchdog, timeout,
  signer check; on any failure the out dir is removed and the previous APK stays), `app_id_for` = `dev.aiappstudio.p<id16>`
  = the device host's `PKG_RE`.
- `core/aas_build/service.py` `build_android`: needs the project's current web build, one build at a time (shared lock with
  web), events `build.started {target android}`, `build.log`, `build.error`, `build.finished {target, status,
  artifactSha256, sizeBytes, signerSha256}` with the APK digest also in the typed `artifact_sha256` column.
- MCP `app_build {target:"android"}`: builds, then, when the studio emulator of this run is running (owner setting on, disk
  gate re-checked), installs and launches the app (`DeviceService.install(launch=True)`: the package reported by the device
  host must equal the project's package id, otherwise nothing is launched). `device_install` now also launches.
- `core/aas_build/capture.py` + MCP `preview_capture {projectId, frame}`: Playwright Chromium (dead proxy for
  non-loopback, WebRTC limited, route filter: same origin/data:/blob: only) on `http://p-<id16>.localhost:<port>/` in
  phone 390x844 / tablet 834x1112 / desktop 1440x900; PNG stored once under `<data>/captures/<sha256>.png`,
  `preview.captured {revision, frame, sha256}`; `GET /api/v1/captures/<sha256>` (owner token, content re-hashed before
  serving, `nosniff`, `default-src 'none'`). Runs on a worker thread (sync Playwright refuses the MCP server's loop).
- S6 low items: R-A `Runner` start purges every `runner_grant:*` row, `runner/run_*.mcp.json`, `runner/runs/*`,
  `runner/tmp/*` (one Runner per backend process); SYSTEM_PROMPT names `plan_submit` first; UI "Require plan approval"
  toggle (owner-only `PUT /api/v1/settings/plan-gate`, box follows the server's answer); plan `contentSha256` stored at
  submit over the canonical JSON of what the card shows (project, run, title, steps), returned in `list_records`, required
  by `POST /plans/<id>/decide` (`contentSha256`, 64 hex), `decide` refuses a mismatch or a stored plan whose text no
  longer matches its hash, and `is_approved*` additionally need `approvedSha256 == contentSha256 == recomputed`
  (an edit after the approval un-approves). UI: a plan without a valid hash is shown unsafe (Approve disabled).
- Fixes found on the way: `run_studio.ps1` assigned `$dev` (= the `[switch]$Dev` parameter, PowerShell names are
  case-insensitive) and failed in every `-Dev` UI mode -> `$devServer`; the mock backend's CORS lacked PUT.

## S7 review fixes (2026-11-23, local commits)
Red first for each item (tests failed against the S7 code, then passed):
- **M1** device install verifies the APK: `DeviceService.install` hashes the bytes it read, compares them with the
  `artifact_sha256` of the project's latest successful android `build.finished`, and installs from a private staged copy
  (`<data>/device/stage/aas-apk-*/app-debug.apk`, `O_EXCL`, mode 0600) of exactly those bytes, re-hashed before use and
  removed afterwards. No recorded build or a different hash -> refused + a `device.log` event. Tests: replaced APK
  refused, no recorded build refused, private copy used (`tests/wiring/test_device_service.py`).
- **M2** `images/android-build/template/gradle/verification-metadata.xml` is committed (390 components, 677 artifacts, each
  with sha256) and the image build runs `--dependency-verification strict` against it; it no longer writes the file
  (`--write-verification-metadata` is gone). The image was rebuilt with the new Dockerfile (exit 0). Probes: unit checks of the committed file
  and the Dockerfile, plus a real Docker probe that deletes one artifact entry and expects "Dependency verification
  failed" (`tests/build/test_android.py`). **Residual:** the initial generation of the committed file was
  trust-on-first-use on 2026-11-23 (it was written by the previous image build from the live repositories and reviewed
  only for completeness, not against an independent source). Changing the dependency set means regenerating it by hand,
  reviewing the diff and committing it.
- **M3** `preview_capture`: per project at most 200 files / 200 MB (oldest pruned, a file another project still holds
  is kept; index in `captures/.index/<project>.json`), PNG cap 8 MiB (was 20), captures refused below 5 GiB free on the
  data drive (`tests/wiring/test_s7_review_fixes.py`). Captures made before this change are not indexed and not pruned.
- **L1** licence: installing the studio accepts the Android SDK licence **on the owner's behalf** (owner decision recorded
  2026-11-23); the image writes the acceptance record `/opt/android-sdk/licenses/android-sdk-license`. The hash in the
  Dockerfile (`9002c006...`) could NOT be verified offline: the zips do not ship the licence text (no package.xml), it
  lives in Google's repository2-3.xml. Recorded as **unverified**; the file is a record, not a gate (AGP never installs).
  **Verified online in S8 (2026-11-23):** `https://dl.google.com/android/repository/repository2-3.xml` (433165 bytes,
  sha256 `b97da160df8d80f0fe67739643cb53fbfcafd9c502ef57b78c038645062865ee`), `<license id="android-sdk-license">` text
  (16962 chars), sha1 of the text with surrounding whitespace stripped (sdkmanager hashes the trimmed licence value) =
  `9002c006f4b8d9a16e715a9fa4df30ddb8abf9d9` = the Dockerfile value (untrimmed text: `efa68a6b...`, not used).
  `platforms;android-36`, `build-tools;36.0.0` and `platform-tools` all reference `android-sdk-license` in that file.
  Hash correct: no change, no image rebuild.
- **L2** stale runner grants are purged by `main()` only after the API port is bound exclusively (`bind_api_socket`,
  `SO_EXCLUSIVEADDRUSE` on Windows), and never for a run of this process that is alive. `create_app` no longer purges.
  Tests: a live run grant survives a second backend that cannot bind (`tests/runner/test_s7_review_fixes.py`).
- **L3** capture timeout: the Playwright driver tree is killed and the worker joined before the capture lock is
  released; a worker that survives the kill releases the lock itself when it ends (no second browser meanwhile).
- **L4** studio keystore + signer record: record written as `.pending` first, then the keystore, then the record is
  renamed; the next start finishes or drops a pending pair (`tests/build/test_s7_review_fixes.py`, both crash points).

## What exists
- `wsl/opt-aas-bin/` (installed root:root to `/opt/aas/bin`, pinned in `MANIFEST.sha256`):
  - `aas-preflight`: one JSON line with the networking mode, kvm, unshare support, `sudo -n -l`, the studio
    AVDs, AVD config pin status, symlinks under `$HOME/.aas`, installed hashes and the WSL listeners.
  - `aas-serve phone|tablet`: `#!/bin/bash -p` (ignores BASH_ENV/ENV). It checks the arguments (exactly one
    verb, not root), that networking is `nat`, `/dev/kvm`, that `$HOME/.aas` has no symlinks, that the AVD .ini
    `path=` matches, and that config.ini matches the pinned copy. Then it runs `flock -n` ->
    `sudo -n runuser -g kvm` -> `env -i <fixed env>` -> `unshare -r -n -m -p -f --kill-child --mount-proc` -> `aas-ns`.
  - `aas-ns`: `ulimit -c 1`, private lo + dummy `d0` fd00::1/64, then `exec python3 -I -S aas_devhost.py`.
  - `aas_devhost.py`: pid 1 of the namespace. It runs the studio adb on 127.0.0.1:5641 (namespace loopback) and
    the emulator with a visible WSLg window: `-gpu host -wipe-data -no-snapshot-save/-load`, restrict=on for
    both nets, port 5600 (phone) or 5602 (tablet), fake HOME `$HOME/.aas/home`, ANDROID_USER_HOME
    `$HOME/.aas/android-user`. After boot it turns on show_touches and pointer_location. The JSON-lines ops
    are tap, swipe, text, install+chunk, uninstall, launch, screenshot, video_start, video_stop and shutdown. Video is
    screenrecord h264 in 48 KiB chunks, base64-encoded. Output queue: control lines go first, and video is
    bounded at 32 chunks with the oldest dropped. It emits a `modal` event when the "Nested Virtualization"
    dialog shows.
  - `aas-phone.config.ini` (1080x2340) and `aas-tablet.config.ini` (1600x2560, 320 dpi): pinned AVD configs.
- `wsl/install.ps1` (owner setup): checks the source hashes, installs with fixed argv, verifies the installed
  files through `\\wsl.localhost` (and refuses reparse points), and copies the manifest to
  `/opt/aas/MANIFEST.sha256`. It then runs `wsl/setup-avd.sh`, which created `aas-tablet`.
- `apps/device_host/launcher.py`: the only place that starts `wsl.exe`. It does this through one Popen
  inside `_popen`. Allowed argv are exactly
  `[%SystemRoot%\System32\wsl.exe, -d, Ubuntu-S9AI-D, --, /opt/aas/bin/aas-serve, phone|tablet]` or
  `.../aas-preflight`. Before every spawn it checks the sha256 of each pinned file through `\\wsl.localhost`.
  The env holds only SystemRoot, windir, SystemDrive and PATH, and cwd is System32. Launches are refused
  below 5 GiB free on C:. `preflight()` requires `nat`, records `sudo -n -l` and refuses AVDs that are not
  aas-*. `DeviceSession` provides the API. A reader thread always drains stdout, and the video queue is
  bounded with the oldest chunk dropped. `python -m apps.device_host.launcher preflight | bridge phone|tablet`
  is the stdio bridge for the backend.
- `apps/device_host/protocol.py` checks requests and device lines: exact key sets, types, 192 KiB per line,
  64 KiB of base64 per chunk.

## Incident and fix: qemu core dumps filled C:
qemu 31.3.9 segfaults on its graceful-exit path (`adb emu kill`, log: `Segmentation fault (core dumped)`).
WSL's core_pattern `|/wsl-capture-crash` wrote about 2.6 GB per dump into `%TEMP%\wsl-crashes` on C:. The main
session deleted 17 of them. Fix: shutdown now sends SIGKILL to the whole pid namespace (`kill(-1)` from pid 1).
`aas-ns` and the harness emulator set `ulimit -c 1`, and the kernel aborts piped core dumps at RLIMIT_CORE=1.
Stale AVD `*.lock` files left by SIGKILL are removed before start, which is safe because of the flock. The
launcher refuses to launch below 5 GiB free on C:. A verified launch after the fix wrote no new dump.

## Review round 1 fixes (2026-11-23)
- Launcher reply admission: a reply is accepted only for an outstanding request id, a screenshot part only for an
  outstanding screenshot request, in sequence, at most 4 MiB per id and 8 MiB over all ids; at most 32
  outstanding ids (a timed-out id stays counted and its late reply is dropped once). Any other line kills the
  session. Tests: 200 000 unsolicited replies and 3000 unsolicited screenshot ids stop at the first line (peak
  traced memory < 2 MiB), per-id and total caps, duplicate reply, part for a non-screenshot request.
- `preflight()` reads at most 64 KiB of stdout (stderr drained and capped); more, or no EOF in time, kills
  wsl.exe and refuses (test: 50 MiB flood).
- `booted` is stored on the session, outside the 200-entry event deque (test: 500-event burst after boot).
- `_bridge`: only JSON objects are forwarded; a backend `timeout` must be a number in (0, 240] s (bool, string,
  NaN, inf, 0, negative, > 240 refused before anything is sent). The `check_disk_space` docstring is raw.
- N7 (final): tap and swipe go through the emulator console (`Console`, see "N7 fix: emulator console");
  text and the fallback still use the persistent adb shell below.
- N7 (first step): tap, swipe and text go through one persistent `adb -P 5641 shell` per session (`InputShell`): each
  command is one stdin line of quoted words plus a unique `echo __aas_<n>__ $?` marker; arguments are still
  validated (ints 0-4096, TEXT_RE). A timeout kills that shell and the next command starts a new one. This
  removes the adb connection and shell start per tap; the `input` command itself still starts app_process in the
  guest. If live N7 still fails, the next step is `sendevent` through the same shell (needs `getevent -p` on the
  live image to map coordinates), or the emulator console `event` command inside the namespace.
- Install: after the sha256 check the devhost reads the APK's binary AndroidManifest.xml (stdlib parser:
  exactly one manifest entry, root `<manifest>`, exactly one `package` attribute) and refuses any package not
  matching `^dev\.aiappstudio\.p[0-9a-f]{16}$` before `adb install`; the APK file is deleted either way. There
  is no aapt2/apkanalyzer in `~/emu/sdk` (no build-tools), so the parser is the check. Allowed packages are
  `pm uninstall`ed first, then `adb install -r -d` (fresh data per build).
- New op `uninstall{pkg}` (same package allow-list, `pm uninstall`). Reply field `pkg` is validated.
- Idle timeout: no request for 15 min (and none in progress) stops the emulator and exits with
  `{"kind":"exit","code":35,"reason":"idle"}`. Video streaming alone does not count as activity.
- Live gate: probes that launch an emulator now use the `emulator_guard` fixture: skip as "deferred" below
  8 GiB free on C:, and any new file in `%LOCALAPPDATA%\Temp\wsl-crashes` is deleted at once and fails the probe.

- Env (DESIGN 2.1: argv `env -i /bin/bash --noprofile --norc aas-devhost.sh <verb>`): the launcher instead
  passes a minimal Windows env to wsl.exe (SystemRoot, windir, SystemDrive, PATH=System32; no WSLENV,
  BASH_ENV, HOME, USERPROFILE), the entry scripts are `#!/bin/bash -p` (BASH_ENV/ENV ignored, no imported
  functions), and `env -i <fixed env>` is applied later, after sudo/runuser and before unshare. The argv tail
  is `/opt/aas/bin/aas-serve phone|tablet` or `/opt/aas/bin/aas-preflight`. Evidence: N4 (canary does not run
  through the launcher; the same argv with the full env does run it), PM3b (spawn env has no
  WSLENV/BASH_ENV/ENV/USERPROFILE/HOME).
- Script names: `aas-serve`, `aas-ns`, `aas-preflight`, `aas_devhost.py` and the two pinned config.ini
  (six files in the manifest) instead of `aas-devhost.sh` / `aas-devhost-ns.sh` (three files).
- Ops: `screenshot`, `video_start{size}` / `video_stop`, `shutdown` instead of `screencap`, `video{on,size}`,
  `stop`; video sizes also include 800x1280 and 540x864 (tablet). `install{sha256,size}` has no `chunks` field
  (the size bounds the chunks). `key{code}` is not implemented (no caller yet). `uninstall{pkg}` is implemented.
- Shutdown sends SIGKILL to the namespace instead of `adb emu kill` (qemu crash on graceful exit, see above).

## N7 fix: emulator console (2026-11-23)
- `input tap` starts app_process in the guest (up to 3.6 s under screenrecord load) and `sendevent` is blocked
  (SELinux). Taps and swipes now use the emulator console of the session, `127.0.0.1:<5600|5602>` inside the
  private net namespace, over one persistent connection (`Console` in `aas_devhost.py`):
  `event mouse <x> <y> 0 1` then `... 0 0` (touch screen device, device pixels); a swipe is a down, up to 100
  moves spread over `ms` and an up. Text stays on the adb path.
- Auth: the token is read only from `$HOME/.emulator_console_auth_token`, and only if `HOME` is exactly
  `$AAS_STATE/home` (the studio fake HOME set by aas-serve), with O_NOFOLLOW, regular file, <= 256 bytes,
  `^[A-Za-z0-9+/=_-]{1,128}$`. It is sent only when the banner asks for auth and only if the token file the
  banner names is that same file; a refused auth or a foreign token file disables the console for the session.
- Validation: x/y are ints inside the booted screen size (`wm size`), ms 1-5000; every line sent must match
  `^event mouse <int> <int> 0 [01]$`. Replies: lines up to `OK`; `KO...` is an error; reply lines and length are
  capped. A timeout closes the connection (the next request reconnects); a connection found dead at the first
  command of a gesture is reopened once and the command resent.
- Fallback: console unavailable before anything was sent (connect/handshake failed) -> the adb `input` path; a
  console error after a command was sent is returned as an error (no adb retry, no double tap).
- Unit tests (fake console on 127.0.0.1): auth, no-auth banner, wrong token, foreign token path, token file
  checks, connection refused, bounds/types, line whitelist, swipe sequence and timing, reconnect after drop,
  timeout then reconnect, KO, host fallback rules, HOME guard. `tests/local_gate`: 100 passed, 20 skipped (live).

## Review fixes (console, harness, receipt) 2026-11-23
- Harness: guest commands enter the session with `nsenter -t <devhost> -n -p` and assert that the session's pid
  namespace differs from the caller's and that the command really ran in it (`INNS == HOSTNS`); an adb client
  can then only auto-start a server inside the session's pid namespace, which dies with it. The guest command
  runs only if the adb server port already listens (`NO_ADB_SERVER` otherwise): no probe starts a server.
  This was the source of the stray `adb -L tcp:5641 fork-server` noted earlier (old `nsenter -n` only).
- Leftover probe: see PM3d row; an incomplete probe (sudo or /proc scan did not finish) counts as a leak.
- Receipt: per-run records and the one-run pass rule (see "Local gate"); tests in `test_receipt_runs.py`.
- Console screen size: `wm size` rc must be 0, lines anchored (`Physical size: WxH`, `Override size: WxH`),
  each side 200-8192, no leading zero (`072x1` is refused). An override that differs from the physical size
  (scaled display) gives no console: console pixels are panel pixels. Unknown size -> no console (adb path).
- Rotation: read from `dumpsys input` (`Viewport INTERNAL ... orientation=N` / `SurfaceOrientation: N`; absent,
  >3 or disagreeing -> no console) at boot and every 2 s afterwards; taps are validated against the rotated
  logical size and mapped to panel pixels (inverse TouchInputMapper transform). An unreadable rotation later
  drops the console for the session. Residual: a rotation in the last <= 2 s maps one gesture wrongly; the
  landscape mapping is unit-tested only (live check was rotation 0).
- Token: sent only if the auth banner names exactly one file and it is the studio token file (a banner without
  a path, or with two paths, disables the console). Line and token regexes use fullmatch (a trailing newline
  no longer passes `$`).
- Touch release: after a touch-down was written, every error path (KO, drop, timeout, failed reconnect) writes
  the matching up at the last position sent (best effort, 1 s, reconnecting if needed) and reports
  ConsoleError; a lost console after a down never falls back to adb.
- Live pixel check (second launch, one session, not part of the gate run): console taps at (531,1207),
  (200,600), (900,2000) were read back from `dumpsys input` as DOWN at (531.0,1206.9), (200.0,599.9),
  (899.9,1999.9). test_02 now records the same check (`last_down_xy`, `tap_landed`); in the gate run its
  extraction cut the dump line before the coordinates (fixed after the run, parser unit-tested).
- Tests: `tests/local_gate` non-live 141 passed, 20 skipped; live gate run 160 passed.

### Findings from this research (not posted on GitHub)

1. **Real bug: unbounded recursion on crafted or corrupt hives, crashing the process.**
   - Where:
     - `LogAnalyzer.Dfir.Core/IO/RawRegistry.cs:100` — `if (sig == "ri") foreach (var o in ListOffsets(off)) yield return o;`
     - `RawRegistry.cs:148-151` — `FindInList` recursing on `ri`.
   - Neither has a visited set or depth limit.
   - I confirmed it with a scratch harness against the PR's `Dfir.Core`: a 0x2000-byte hive whose root subkey list is an `ri` cell pointing to itself makes `new RawRegistry(..).OpenKey("x")` die with **"Stack overflow." and exit 134**. A `try/catch` cannot catch this in .NET.
   - Impact: any hive in the evidence (SYSTEM/SOFTWARE/NTUSER/Amcache/USB/services parsers all use `RawRegistry`) can kill the whole investigation or App. That breaks the PR's own "FAILED, never silent" contract.
   - For comparison, `CompoundFile.cs:87` does guard its chain loops with a `HashSet`.
   - Also unbounded in `RawRegistry`: the subkey count `n` is not checked against the cell length. That throws `ArgumentOutOfRange`, which is caught, so it is only cosmetic.
2. **Regexes without a match timeout run over adversarial evidence.**
   - Where: `Detection/SigmaLite.cs:132` (`Regex.IsMatch(actual, expected)` for `|re`) and `Detection/YaraLite.cs:161,175,182` (`new Regex(...)` with no `matchTimeout`).
   - The rules are shipped or operator-supplied, but the inputs are evidence. Add `TimeSpan` timeouts and report a timeout as UNDETERMINED or FAILED.
3. **Minor:** `Acquisition/RemoteCollection.cs:91` puts `r.CaseId` into a `#` comment line of the generated PowerShell without removing CR/LF. `Operator` is sanitized. The CaseId is app-generated, so the risk is low, but sanitize it the same way.
4. **Portability (non-blocking):**
   - `LogAnalyzer.Dfir.Core` targets portable `net10.0` but relies on Windows `System.IO.Path` semantics for evidence paths: 43 calls to `Path.GetFileName`/`GetDirectoryName`/… on strings like `C:\Users\...`.
   - On Linux these return the whole string. That is the cause of most Linux-only test failures below.
   - Either target `net10.0-windows` or use an explicit Windows-path helper.

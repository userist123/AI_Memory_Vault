# RCD Theme: Churn & Retention

Part of the `revenue-centric-design` lens — see `revenue-centric-design.md` for the hard gambling-use restriction and attribution requirement before applying anything below.

## Principle: "Retention is built, not requested"

- **Apply when:** designing a cancellation flow, a win-back email, or any retention-facing moment.
- **The move:** perceived *loss* retains users more effectively than promised future benefit — so retention should be engineered into the product experience beforehand (progress the user would lose, data they've accumulated, a streak they'd break), rather than requested reactively at the cancellation screen with a discount offer.
- **Evidence:** grounded in loss-aversion research broadly (people weigh a loss roughly twice as heavily as an equivalent gain) — the source applies this specifically to argue that retention "asks" (please don't go, here's 20% off) underperform retention that's structurally built into the product beforehand.
- **Visual:** a cancellation flow that surfaces what the user specifically accumulated and would lose (saved projects, streak, custom settings) rather than only a discount coupon.

## Gotcha this theme flags explicitly

The source itself distinguishes real, structural loss-aversion design from dark patterns — don't manufacture artificial scarcity or fake loss framing that doesn't correspond to something genuinely true about the user's account. Applying this principle honestly (showing real accumulated value) is different from applying it manipulatively (inventing urgency that isn't real); only the former is in scope here.

# RCD Theme: Onboarding & Activation

Part of the `revenue-centric-design` lens — see `revenue-centric-design.md` for the hard gambling-use restriction and attribution requirement before applying anything below.

## Principle: "Value first, ask later"

- **Apply when:** designing a signup flow, first-run experience, or any moment that asks the user for something (email, payment info, permissions) before they've experienced the product's value.
- **The move:** sequence the flow so proof of value arrives before the ask — let the user feel the payoff before they're asked to commit anything. Asking too early forces the user to evaluate the product on faith rather than evidence, right at the point they're most likely to bounce.
- **Evidence:** framed by the source as a recurring failure pattern in SaaS onboarding — flows that ask for payment or heavy commitment before any value delivery show materially worse activation than flows that defer the ask.
- **Visual:** a product that lets someone complete one real, useful action (import a file, see a generated result) before hitting a signup wall — versus a wall shown on landing.

## Principle: neutrality is a design choice, not a null state

- **Apply when:** any first-run screen, empty state, or setup step that could passively wait for the user to figure out what to do next.
- **The move:** an interface that doesn't actively direct the user toward the next best action is making a choice — just a bad one, by omission. Empty states and first-run screens should point at one clear next step rather than presenting a blank canvas.
- **Evidence:** cited as a general pattern across the source's onboarding critiques — passive, undirected first-run screens correlate with lower activation than screens with one obvious call to action.
- **Visual:** an empty dashboard with a single prominent "create your first X" action, rather than an unguided blank grid.

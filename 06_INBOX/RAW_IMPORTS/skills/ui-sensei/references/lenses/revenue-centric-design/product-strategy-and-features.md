## Principle: default is a feature-scoping decision, not just a UI one

- **Apply when:** deciding which features are on by default versus opt-in for new accounts.
- **The move:** which capabilities a new user encounters by default shapes what they perceive the product to *be*, independent of what's actually available behind a settings toggle. Default-on features should be the ones that demonstrate the product's core value fastest, not necessarily the ones with the deepest engineering investment.
- **Evidence:** general extension of the same default-effect reasoning applied to pricing in `pricing-and-monetization.md` — the source treats "default" as a recurring lever across pricing, onboarding, and feature exposure alike, not a pricing-specific trick.
- **Visual:** a new workspace that opens with 2-3 pre-configured, immediately useful views rather than a blank slate requiring setup before any value is visible.

Thoroughly study the entire project first, including source code, configuration,
documentation, tests, and existing context files, so the implementation strategy
is grounded in the project’s real architecture, constraints, and priorities.

Then create a complete, execution-ready implementation plan organized by phases
inside `.context/04-implementation-plan`, with one Markdown file per phase using
zero-padded sequential filenames like `01-phase.md`, `02-phase.md`, and `03-phase.md`.
In each phase file, include the phase objective, scope boundaries, prerequisites and dependencies,
detailed ordered implementation steps, affected modules or files, validation and testing approach,
data or migration impacts, risks and mitigations, rollback approach, and clear completion criteria.

Also create `.context/04-implementation-plan/README.md` as the master index that lists phases in order,
summarizes each phase, and shows cross-phase dependencies and milestones.

Keep the plan specific, actionable, and directly aligned with the current codebase state
and architecture documentation, avoiding generic recommendations.

## 1. Executive Summary

This document formalizes the runtime integration contract between the administrative orchestration layer (`MemoryController`) and the offline retrieval engine (`HybridRetriever`).

```text
┌─────────────────────────────────────────────────────────────┐
│                 MemoryController.search()                   │
│  - Primary Authorization (Principal, Operation.SEARCH)      │
│  - Query Sanitization & Rate-limiting                       │
│  - Pagination Token Handling (HMAC-SHA256)                  │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│          RetrievalBoundaryAdapter (Pure Adapter)            │
│  - Principal Identity Normalization (HUMAN, AI_AGENT, ADMIN)│
│  - Trust Boundary Enforcement: "Narrow, Never Broaden"      │
│  - Filter Validation & Canonical Mapping                    │
│  - Post-retrieval Defense-in-Depth Leak Sanitize            │
│  - Audit Trace & Request-ID Binding                         │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                       HybridRetriever                       │
│  - Multi-Signal RRF (BM25 + Entity + Dense-fallback)        │
│  - Deterministic Lexicographical Secondary Tie-Breaking     │
│  - Pure In-Memory Read-Only Traversal                       │
└─────────────────────────────────────────────────────────────┘
```

The adapter guarantees that no caller—regardless of privilege or prompt injection—can widen retrieval beyond the canonical trust boundary (`ACTIVE + verified`), while allowing granular narrowing by note type or explicit boundary filters.

## 2. Formal Principle: "Caller May Narrow, Never Broaden Trust Boundary"

### Formal Mathematical Specification

Let $\mathcal{U}_{lifecycle}$ and $\mathcal{U}_{verification}$ denote the universe of all recognized lifecycle and verification states across the vault:
$$\mathcal{U}_{lifecycle} = \{\text{ACTIVE, REVIEW, ARCHIVED, RAW, RECONSOLIDATING, SUPERSEDED, CLASSIFIED, NORMALIZED, VERIFIED, NONE}\}$$
$$\mathcal{U}_{verification} = \{\text{verified, unverified, ai\_generated, unknown}\}$$

Let $\mathcal{B}$ denote the immutable secure trust boundary:
$$\mathcal{B}_{lifecycle} = \{\text{"ACTIVE"}\}$$
$$\mathcal{B}_{verification} = \{\text{"verified"}\}$$

For any retrieval request with caller-supplied filters $F_{lifecycle} \subseteq \mathcal{U}_{lifecycle}$ and $F_{verification} \subseteq \mathcal{U}_{verification}$:

1. **Admissibility Condition (Subset Invariant)**:
   $$F_{lifecycle} \subseteq \mathcal{B}_{lifecycle} \quad \wedge \quad F_{lifecycle} \neq \emptyset$$
   $$F_{verification} \subseteq \mathcal{B}_{verification} \quad \wedge \quad F_{verification} \neq \emptyset$$

2. **Broadening Rejection (Fail-Closed)**:
   If $\exists l \in F_{lifecycle} \text{ such that } l \notin \mathcal{B}_{lifecycle}$, or $\exists v \in F_{verification} \text{ such that } v \notin \mathcal{B}_{verification}$:
   $$\text{Result} = \text{Raise } \texttt{BoundaryViolationError}$$

3. **Narrowing Permission**:
   - Callers are allowed to supply $F_{types} \subseteq \mathcal{U}_{types}$ (e.g. `types=["procedure"]`) to narrow results to a specific knowledge domain.
   - Callers are allowed to explicitly specify $F_{lifecycle} = \{\text{"ACTIVE"}\}$ or $F_{verification} = \{\text{"verified"}\}$, but any superset or alternative is rejected.

4. **Empty Set Defense**:
   If $F_{lifecycle} = \emptyset$ or $F_{verification} = \emptyset$, the request is rejected with `FilterValidationError`. An empty filter set must never be allowed to act as an open wildcard.

## 3. Detailed Data Contract

### 3.1 Input Payload (`RetrievalRequest`)

The retrieval boundary accepts a neutral, immutable `RetrievalRequest`:

| Field | Type | Mandatory? | Description |
|---|---|---|---|
| `query` | `str` | **Yes** | Natural language or keyword search query (non-empty string). |
| `principal` | `Union[Principal, str]` | **Yes** | The caller identity. Must normalize to `"human"`, `"ai_agent"`, or `"admin"`. |
| `top_k` | `int` | No (default: 10) | Maximum number of ranked hits to return ($k > 0$). |
| `lifecycles` | `Optional[Iterable[str]]` | No | If omitted, defaults to `{"ACTIVE"}`. If provided, must be a subset of `{"ACTIVE"}`. |
| `types` | `Optional[Iterable[str]]` | No | Optional narrowing filter (e.g. `["procedure", "decision"]`). |
| `verification` | `Optional[Iterable[str]]` | No | If omitted, defaults to `{"verified"}`. If provided, must be a subset of `{"verified"}`. |
| `audit_ref` | `Optional[str]` | No | Upstream audit tracking reference / hash from MemoryController. |
| `request_id` | `Optional[str]` | No | Trace correlation identifier. |

### 3.2 Principal Representation & Propagation

The principal represents the identity and authority tier executing the operation:
- **`Principal.HUMAN` / `"human"`**: Human operator interacting via CLI, Obsidian, or direct prompt.
- **`Principal.AI_AGENT` / `"ai_agent"`**: Autonomous or semi-autonomous LLM agent (Claude Code, Antigravity, etc.).
- **`Principal.ADMIN` / `"admin"`**: Administrative or security auditing process.

**Propagation Rules**:
1. The caller principal MUST be validated at the boundary via `RetrievalBoundaryAdapter.normalize_principal()`.
2. Missing principal (`None` or `""`) raises `PrincipalValidationError`.
3. Unrecognized principal string (e.g. `"guest"`, `"anonymous"`) raises `PrincipalValidationError`.
4. The normalized principal string is embedded into `RetrievalResponse.principal` and `trace["caller_principal"]` to maintain cryptographic audit chain continuity.

### 3.3 Semantic Definitions of Vault Lifecycle States

| Lifecycle State | Definition | Eligibility in Secure Retrieval | Reason |
|---|---|---|---|
| `ACTIVE` | Canonical, fully verified, production-ready knowledge. | **ELIGIBLE** (Default) | Authoritative source of truth for runtime reasoning. |
| `REVIEW` | In-flight note proposed by an agent or pending human attestation. | **FORBIDDEN** (Excluded) | Invariant I-003 & I-004. Unattested notes must not leak into agent context to prevent hallucination loops. |
| `RAW` | Untrusted external input from inbox (`06_INBOX/RAW_IMPORTS/`). | **FORBIDDEN** (Excluded) | Raw evidence only. Never canonical. |
| `RECONSOLIDATING` | Note currently undergoing schema migration or algorithmic synthesis. | **FORBIDDEN** (Excluded) | Intermediate transient state; content in flux. |
| `ARCHIVED` | Retired, deprecated, or superseded historical notes. | **FORBIDDEN** (Excluded) | Retained for historical provenance only; obsolete procedures must not guide active agents. |
| `SUPERSEDED` | Note that has been replaced by a newer version via `superseded_by`. | **FORBIDDEN** (Excluded) | Prevents conflicting or obsolete facts from being retrieved. |
| `NONE` | Note with missing or unparseable lifecycle header. | **FORBIDDEN** (Excluded) | Fail-closed defense against frontmatter corruption. |

### 3.4 Verification States

| Verification State | Definition | Eligibility |
|---|---|---|
| `verified` | Formally attested by Human/Admin or authoritative execution proof. | **ELIGIBLE** (Default) |
| `unverified` | Self-proposed note without human attestation. | **FORBIDDEN** |
| `ai_generated` | Unattested AI draft. | **FORBIDDEN** |
| `unknown` | Missing verification field. Treated as unverified. | **FORBIDDEN** |

## 4. Output Envelope & Provenance Trace (`RetrievalResponse`)

The adapter emits an immutable, audit-ready `RetrievalResponse`:

```python
@dataclass
class RetrievalResponse:
    hits: List[Hit]                     # Ranked list of verified Hit objects
    total_hits: int                     # Total count of returned hits
    query: str                          # Original query string
    principal: str                      # Normalized caller principal ("human", "ai_agent", "admin")
    effective_lifecycles: List[str]     # Enforced lifecycles (["ACTIVE"])
    effective_verification: List[str]   # Enforced verification (["verified"])
    effective_types: Optional[List[str]]# Narrowing types if applied
    trace: Dict[str, Any]               # Detailed rank trace for audit
    audit_ref: Optional[str]            # Upstream audit hash/token
    request_id: Optional[str]           # Request identifier
    timestamp_utc: str                  # ISO-8601 UTC timestamp
```

### Trace Integrity
The `trace` dictionary captures:
1. `candidate_rankings`: Top-k candidate note IDs per retrieval arm (`bm25`, `entity`, `dense`).
2. `fused_ranking`: Combined RRF score and component signal ranks for each hit.
3. `latency_ms`: Total execution latency in milliseconds.
4. `caller_principal`: Verified principal identifier.
5. `boundary_filters`: Audit snapshot of exact filters applied.

## 5. Security Error Handling (Fail-Closed)

All security, validation, and boundary errors fail immediately without returning partial or degraded results:

| Error Scenario | Exception Class | Base Class | HTTP Status Equivalent |
|---|---|---|---|
| Missing or empty principal | `PrincipalValidationError` | `RetrievalBoundaryError` | 400 Bad Request |

## 6. Runtime Audit & Defense-in-Depth Verification

To eliminate any possibility of trust boundary leakage:
1. **Pre-Retrieval Gate**: The adapter validates caller-supplied arguments before calling `HybridRetriever`. Any violation aborts execution.
2. **Post-Retrieval Sanitize Loop**: Even if the underlying retrieval algorithm or index somehow produced a note with `lifecycle != "ACTIVE"` or `verification != "verified"`, the adapter runs a secondary deterministic sanitize loop:
   ```python
   for h in hits:
       if h.note.lifecycle not in ALLOWED_SECURE_LIFECYCLES:
           continue
       if h.note.verification not in ALLOWED_SECURE_VERIFICATION:
           continue
       sanitized_hits.append(h)
   ```
3. **Storage Immutability Audit**: The boundary adapter executes zero file operations, zero writes, and zero mutations on storage. Verified via `test_boundary_zero_storage_mutation`.

## 8. Integration Roadmap (When Wiring into MemoryController)

When `MemoryController.search()` is subsequently updated:
1. **Instantiate Adapter**: `self.retrieval_adapter = RetrievalBoundaryAdapter(HybridRetriever(index))`
2. **Translate Call**: Forward `MemoryController.search(principal, query, ...)` into `RetrievalRequest(query=query, principal=principal, ...)`
3. **Audit Log Integration**: Bind `resp.trace` directly into `memory_controller.audit.logger.audit_event("search", principal, target_id, success=True, details=resp.trace)`
4. **Pagination Token Compatibility**: Use `resp.total_hits` and `offset` inside existing HMAC-signed `PaginationToken` without altering token wire format.

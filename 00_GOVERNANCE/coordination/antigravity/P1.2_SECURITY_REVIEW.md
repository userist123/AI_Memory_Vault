## 1. Problem Found

`secure_search()` in `hybrid_retrieval.py` (pre-P1.2) had a **trust boundary widening vulnerability**:

```python
# BEFORE (vulnerable):
def secure_search(self, query, top_k=10,
                  allowed_lifecycles=None, allowed_types=None, allowed_verification=None):
    return self.search(
        query=query, top_k=top_k,
        allowed_lifecycles=allowed_lifecycles or {"ACTIVE"},  # <-- bypass possible
        allowed_types=allowed_types,
        allowed_verification=allowed_verification or {"verified"},  # <-- bypass possible
        secure=True,
    )
```

### Attack Vectors Identified

| Vector | Exploit | Impact |
|--------|---------|--------|
| **V1** `allowed_lifecycles=["REVIEW"]` | Replaces `{"ACTIVE"}` entirely | REVIEW notes (unattested, in-flight) leaked |
| **V2** `allowed_lifecycles=["ACTIVE", "REVIEW"]` | Adds REVIEW alongside ACTIVE | Same as above |
| **V3** `allowed_lifecycles=["ARCHIVED"]` | Full override | Archived/stale notes leaked |
| **V4** `allowed_lifecycles=["RAW"]` | Full override | Unprocessed inbox notes leaked |
| **V5** `allowed_lifecycles=["RECONSOLIDATING"]` | Full override | Notes in consolidation leaked |
| **V6** `allowed_verification=["unverified"]` | Replaces `{"verified"}` | AI-generated / unverified notes in results |
| **V7** `allowed_verification=["admin"]` | Unknown value silently accepted | Unpredictable: notes with typo'd verification slipped through |
| **V8** `allowed_lifecycles=[]` | Empty set → `or {"ACTIVE"}` *is not triggered* when list evaluates falsy, but `set()` is falsy → *actually* OK | Subtle bug: `[] or {"ACTIVE"}` = `{"ACTIVE"}`, but `set()` passed as arg would slip |
| **V9** `allowed_lifecycles=["XYZZY"]` | Unknown lifecycle silently accepted | Zero results but no error — silent failure |

> **Root cause**: The `or` operator in Python treats `allowed_lifecycles or {"ACTIVE"}` as "use the caller's value if truthy". Any non-empty list/set from the caller **bypasses the default entirely** and substitutes whatever the caller requested — including forbidden states.

### Why REVIEW is Explicitly Excluded

REVIEW lifecycle notes are **in-flight**. They have not yet been human-attested via `Principal.HUMAN`/`Principal.ADMIN` via `Operation.ATTEST` (invariant I-004). Allowing REVIEW into a secure retrieval path would violate invariant **I-003** (Creation Lifecycle Restricted) and **I-004** (Attestation Authorization).

## 2. Final Policy — Fail-Closed `secure_search()`

```
PRINCIPLE: Callers may RESTRICT but never WIDEN the trust boundary.
```

### Constants (module-level, frozen)

```python
ALLOWED_SECURE_LIFECYCLES  = frozenset({"ACTIVE"})
ALLOWED_SECURE_VERIFICATION = frozenset({"verified"})

_KNOWN_LIFECYCLES   = frozenset({"ACTIVE", "REVIEW", "ARCHIVED", "RAW", "RECONSOLIDATING", "NONE"})
_KNOWN_VERIFICATION = frozenset({"verified", "unverified", "ai_generated", "unknown"})
```

### Enforcement Rules (checked in this order)

1. **Empty set check**: `allowed_lifecycles=[]` → `SecureFilterViolation` (empty set = no boundary = bypass)
2. **Unknown value check**: any value not in `_KNOWN_LIFECYCLES/_KNOWN_VERIFICATION` → `SecureFilterViolation`
3. **Boundary excess check**: any value outside `ALLOWED_SECURE_*` → `SecureFilterViolation`

`SecureFilterViolation` is a `ValueError` subclass raised **before any retrieval** occurs — no partial results are returned.

## 5. Limitations

1. **`search()` is not hardened**: The lower-level `search(secure=True, allowed_lifecycles=...)` still accepts any value. The hardening is **only on `secure_search()`**. Callers that bypass `secure_search()` and call `search()` directly with `secure=True` are not protected by this change.

2. **`allowed_types` is not boundary-enforced**: No whitelist for note types has been defined. Callers can pass any `allowed_types` value. If type-based security is needed (e.g. to exclude `experimental` types from secure results), it must be added in a follow-up.

3. **`RECONSOLIDATING` is in `_KNOWN_LIFECYCLES`** but does not appear in all vault notes — it is included for completeness and future-proofing.

4. **Module-level constants are not sealed**: Python has no way to truly prevent mutation of `frozenset` references at runtime. In a production environment, these constants should be loaded from a signed configuration source and verified at startup.

5. **No logging/audit on `SecureFilterViolation`**: Violations are raised but not logged to an audit trail. When integrated with `MemoryController`, all violations should be sent to the tamper-evident audit log (invariant chain per I-001..I-012).

---

## 6. Required Actions After Integration with `MemoryController`

When `MemoryController.search()` is wired to use `HybridRetriever`:

1. **Route through `secure_search()`**, not `search()` directly.
2. **Catch `SecureFilterViolation`** and log it to the tamper-evident audit chain (do not silently swallow).
3. **Propagate `Principal` context** from the `MemoryController` call into the retrieval path so violations can be attributed to the requesting agent.
4. **Add `allowed_types` enforcement** if `experimental` or `navigation` types must be excluded from secure results by default.
5. **Consider `I-RETRIEVAL` invariant**: the retrieval path must go through `MemoryController.search()` exclusively — direct instantiation of `HybridRetriever` by external code bypasses I-RETRIEVAL. This module's `secure_search()` is a defense-in-depth layer, not a substitute for the authorization chain.
